## 已知限制与待办

- TcpServer 在 baseLoop 线程、事件分发之外同步析构；没有显式异步 stop，析构不保证待发数据排空。业务层优雅下线由应用组织。
- Acceptor 仅分类并记录 EMFILE；持续耗尽 fd 时可能反复触发监听事件，恢复策略待定。
- 没有连接空闲或输出排空超时。对端 EOF 后若停止读取，输出排空可能长期等待，可由应用请求 forceClose。
- 当前仅支持 IPv4，默认 Poller 工厂仅提供 epoll 后端。
- 公网小包吞吐平台的具体限制位置尚未定位；原始压测产物与临时客户端位于仓库外，独立服务端极限及同地域客户端对照尚未验证。

## 最近验证

2026-11-05 的代码验证：

- 完整 Debug 构建与 32/32 项 CTest 通过，包含 NDEBUG 专项及正式回声程序子进程回归。
- 两种安装布局迁移后的四组 Debug/Release 独立使用方验证通过。
- Release 验证范围为独立使用方与回声程序专项，不代表协程原型已通过 Release 回归。

2026-11-06 首轮压测（Release + WARN 日志补丁，`--threads 1`）：

- 跨端：EIP 固定带宽 3 Mbps，JMeter 5.6.3 长连接 5 字节 ping-pong；200 并发 5,607 QPS（约 2.65 Mbps），500/1000 并发稳定在 6.0–6.3k QPS；1000 并发时服务端约 8% CPU、系统 idle 88–93%，表现与出向带宽限制一致。
- 回环：临时 epoll 客户端与服务端共享 2 vCPU，单 IO 线程配置下最高观测值为 105,495 QPS（2 客户端 × 64 连接），CPU 占用较高；连接数增加后回落到 6.6–7.8 万 QPS，尚未隔离客户端与服务端各自的容量。
- 延迟、带宽实测、误差口径和后续建议见 [benchmark-plan.md](benchmark-plan.md)。

2026-11-07 第二轮压测（EIP 峰值 50 Mbps）：

- 家宽 JMeter 5 B：1000 并发 27,510.5 QPS（0 错误，p95 41 ms），2000 并发 28,682.4 QPS（8 错误，按总 samples 约 0.0005%，p95 96 ms）；WSL loopclient 在 1000/2000/3000 连接下约 2.7–2.9 万 QPS，形成吞吐平台，未定位具体限制点。
- payload 扫描（2000 连接）：5/64 B 约 29.3k QPS，256/1024 B 降到 19.3k/5.3k QPS，含协议开销的带宽估算约 48–49/45 Mbps，与 50 Mbps 限制接近；转折位于已测的 64–256 B 区间。
- 手机热点约 4.6k QPS；该对照同时改变客户端网络与服务端端口，说明路径和条件影响结果，尚不能定位家宽平台或排除云侧网络限制。
- 服务端 3000 连接时约 30–34% CPU（按单核 100% 口径）、系统 idle 67–72.5%；本机回环 71.5k QPS（1000 连接），`--threads 2` 78.1k。访问自身 EIP 未完成回声事务，原因未验证。详细表格、统计边界与收尾事项见 [benchmark-plan.md](benchmark-plan.md)。
